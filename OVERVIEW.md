Runs Command Code agents inside Paseo as a provider, so a Command Code session sits beside your Claude Code, Codex, and other agents with the same worktrees, diffs, terminals, and mobile clients.

Command Code exposes its agent over the Agent Client Protocol on stdio. This plugin registers that ACP server as a Paseo provider, so Paseo owns the process and session lifecycle and Command Code keeps supplying the models, modes, and tools.

Setup: install the Command Code CLI on the daemon machine (`npm i -g command-code`) and sign in once with `cmd login`. The provider appears in the model picker as Command Code. For headless or CI daemons, set `COMMAND_CODE_API_KEY` instead of signing in. The plugin looks for the CLI as `cmd` (or `cmdc` on Windows) and reports it as unavailable when the binary or the login is missing.

Command Code's own model catalog, reasoning effort options, and permission modes (Standard, Accept Edits, Plan, Don't Ask, Bypass Permissions) are available in the composer, along with image prompts. Sessions persist and can be resumed, because the ACP server supports session load and resume. Paseo does not inject its tool set: the agent uses its own tools, and file edits and shell commands flow through Paseo's normal permission prompts.

A Paseo session system prompt is honored. Command Code's ACP server has no field for one, so the plugin ships a small Command Code mod that returns the prompt from its `appendSystemPrompt` hook. Each Command Code process the provider spawns stages the prompt Paseo sends at session start in a prompt file of its own — allocated inside the transport, so a provider connection's other children (catalogs, discovery) can never collide with or delete it — hands that file to the mod, and deletes it when that process exits, so any agent that sets a system prompt, such as an Agent Room seat, starts with it. The mod re-reads the file when its cached read was empty, so a hook call that lands before Paseo's session request does not pin an absent prompt for the session. The mod itself lives in the plugin's data directory and is rewritten whenever the plugin's copy changes.

Subagents are first-class too: each Command Code `agent`/`task` delegation appears in Paseo's Subagents panel with its own timeline, so the inner tool steps stream live instead of collapsing into a single "Agent" tool call. Background subagents are collected when the parent reads their result with `agent_output`.

Paseo's usage view also shows Command Code's plan and quota, so you do not need to open the Command Code website to check it. It reports the 5-hour and weekly limits, remaining monthly, purchased, and free credits, cloud minutes when available, the billing period, and request and token counts. The data comes from the same Command Code endpoints that back the CLI's `/usage` overlay; they are not a documented public API and may change.

The plugin reads the API key from `COMMAND_CODE_API_KEY` or `~/.commandcode/auth.json` to query those usage endpoints, and it does not log or store the key. The provider status probe still only checks that a login exists. To point at a different binary or environment, set `command` or `env` under `agents.providers.command-code` in `~/.paseo/config.json`.
